## 動作確認手順

READMEの順にインストール・マイグレーション・管理者作成・起動。キーなしでユーザー登録→PEERルーム作成→原文投稿→Markdown生成→履歴から保存。管理画面で推奨モデルとキーを保存→文章/TTS接続テスト→音声ON→講師登録→AIルーム作成→候補確認・編集送信→講師回答→発話→MP3。動画は課金確認つき接続検証→動画ON→同一スナップショット選択→生成→プレビュー／保存。

## 実API検証に必要なもの

GeminiとOpenAIのAPIキー、対象モデルの利用権限、課金枠。キーは管理画面に登録でき、チャットに貼る必要はない。初期値はGemini文章 `gemini-3.8-flash`、OpenAI音声 `gpt-realtime-2.1-mini` / marin、Gemini動画 `gemini-omni-1.1-flash`。接続結果で実際の利用可否を判断する。モデルが使えない場合に黙って他モデルへ切り替えない。

## 既知の制約・後続への引継ぎ

- Gemini/OpenAI実APIはキー登録待ち。コードとMockテストが動くことを実API成功としていない。
- パスワード再設定は運用者への連絡案内。メール配送基盤は未導入。
- 管理一覧はサーバー側でlimit/offsetページングし、状態・公開範囲・ログの期間とレベルで絞り込む。1応答の取得上限は200件。
- 字幕同期は発話単位。口パク、単語単位同期は対象外。
- 映像はインラインBase64とGoogle公式のURI配送に対応。URIはGoogleホストに限定し、Files APIでACTIVEを待って公式SDKで取得する。未完了・不正形式・サイズ超過は成功にしない。
- 同時ジョブは1件。予算は運用者の保守的なシーン費用上限に基づく受付制限で、外部事業者の実請求額を保証する機能ではない。
- 実機iPadのソフトキーボードとVoiceOverの手動確認、元画像との人物素材一致、Phase 26の本番リリース監査は未実施。
- 開発ブラウザの検証用アカウントは一般的な既定パスワードを残さずランダム化済み。継続運用では`npm run admin:create`で利用者自身の管理者を作成する。

# PDF出力と管理設定

- PDFを既存のスナップショット・ジョブ・保存期限・権限チェックに統合。Markdownと同じテキスト教材スイッチで制御。
- `.env`のフォント・コード用フォント・サイズ・用紙を標準値にし、管理画面の保存値を優先。標準値へのリセットと未保存設定のプレビューを追加。
- IPAex二書体をライセンス付きで同梱しPDFに埋め込み。背景画像・丸型アバター・吹き出し・白いタイトル枠を表示。外部画像とHTMLは実行・取得しない。
- 生成受付時の設定を固定し、設定・描画版の変更で既存PDFキャッシュを再利用しない。37件のテストと本番ビルド、複数ページの描画を検証。
